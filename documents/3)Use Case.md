# Use Case 문서: AI 기반 미디어 모니터링 시스템

## 1. Actor 정의

| Actor | 설명 |
|------|------|
| 기자 | 기사 작성 및 이슈 탐색 |
| 편집자 | 콘텐츠 방향 검토 |
| 데스크/의사결정자 | 전략적 판단 |
| 시스템 | 데이터 수집 및 AI 분석 수행 |

---

## 2. 주요 Use Case 시나리오

### UC-01: 대시보드 접속 및 전체 이슈 확인

#### Preconditions
- 시스템 정상 작동
- 데이터 최신 상태 유지

#### Main Flow
1. 사용자: 대시보드 접속
2. 시스템: 최신 데이터 로드
3. 시스템: 트렌드 이슈 표시
4. 사용자: 주요 이슈 확인

#### Verification:
- 표시된 이슈가 최신 데이터 기반인지 검증

---

### UC-02: 랭킹 뉴스 비교 분석

#### Main Flow
1. 사용자: 비교 메뉴 선택
2. 시스템: 매체별 랭킹 데이터 로드
3. 시스템: 비교 시각화 제공
4. 사용자: 차이 분석

#### Verification:
- 각 매체 데이터 정합성 확인

---

### UC-03: AI 이슈 클러스터 확인

#### Main Flow
1. 사용자: 이슈 클러스터 클릭
2. 시스템: 클러스터 데이터 표시
3. 사용자: 상세 확인

#### Verification:
- 클러스터 정확도 평가

---

### UC-04: 낙종 탐지

#### Main Flow
1. 사용자: 낙종 메뉴 접근
2. 시스템: 경쟁사 vs 자사 비교
3. 시스템: 미보도 이슈 표시
4. 사용자: 확인

#### Verification:
- 낙종 기준 적용 여부 확인

---

### UC-05: 구독자 분석

#### Main Flow
1. 사용자: 구독자 분석 클릭
2. 시스템: 7일 변화 데이터 표시
3. 사용자: 변화 추세 확인

#### Verification:
- 데이터 기간 정확성 확인

---

### UC-06: 댓글 분석

#### Main Flow
1. 사용자: 댓글 분석 클릭
2. 시스템: 댓글 수 기반 인기 표시
3. 사용자: 반응 확인

#### Verification:
- 댓글 수 집계 정확성 검증

---

### UC-07: AI 리포트 확인

#### Main Flow
1. 사용자: 리포트 페이지 접근
2. 시스템: 요약 생성
3. 사용자: 내용 검토

#### Verification:
- 요약 내용 핵심 반영 여부 검증

---

## 3. 예외 처리 (Exception Handling)

| 상황 | 원인 | 대응 |
|------|------|------|
| 데이터 수집 실패 | 크롤링 오류 | 재시도 및 알림 |
| 데이터 누락 | API 문제 | fallback 데이터 사용 |
| AI 오류 | 모델 문제 | 재분석 수행 |
| 데이터 지연 | 네트워크 | 캐시 데이터 표시 |
| 중복 클러스터 | 유사도 오류 | 클러스터 재정렬 |

---

## 4. 비즈니스 룰

- 뉴스 데이터 주기적 수집
- 유사도 기반 클러스터링
- 낙종 기준: 경쟁사 다수 + 자사 없음
- 구독자 일 단위 기록
- 댓글 = 관심도 지표

## 5. 데이터 흐름

2. 데이터 저장 (PostgreSQL)
3. AI 분석 (클러스터링/요약)
4. UI 전달
